## 本 Fork 新增功能

### 1. 扫描枪窗口关闭与最小化

“简易条码扫描”窗口右上角按钮的行为已调整：

* 点击 **×**：关闭扫描枪窗口，停止摄像头工作，并返回主窗口；
* 点击 **−**：读取“功能设置 → 最小化时隐藏到托盘区”：

  * 开启时最小化到托盘；
  * 关闭时正常最小化到任务栏；
* 删除窗口顶部关于 × / − 的说明文字。

### 2. 新增“后处理设置”页面

“设置 → 后处理设置”是本 Fork 新增的页面。

该页面采用全局规则模式：

* 最上方有四个模块复选框：

  * 截屏识别
  * 摄像头识别
  * 本地图片识别
  * 扫描枪
* 所有勾选模块共享同一份规则列表；
* 支持“新增规则”和“删除规则”，规则编号自动更新；
* 每条规则头部显示“规则 N:”，冒号后直接是名称/描述输入框，不另设标签；
* 名称只作备注，不参与匹配，保存为 ruleN_name。

规则按照列表顺序执行：

1. 规则从上到下依次尝试；
2. 第一条匹配成功的规则立即返回结果并停止；
3. 全部规则未匹配时返回原始扫描文本；
4. 未勾选的模块只扫描，不执行正则；
5. 空正则、非法正则、match 不存在、捕获组不存在时跳过该规则，继续下一条；
6. match 和捕获组设置只接受数字和“/”，规则同 matchAll 方法下标的定义，两处需要成对设置，捕获结果无缝连接。

#### 示例

    正则：\d,(\d{10}),(\d{8}),\d
    match：0/2
    group：1/2

输入：

    1,1234567890,20251231,9;2,2345678901,20260101,8;3,3456789012,20260202,7

输出：

    123456789020260202

#### 约束

* match 和捕获组的项数必须相同；
* 点击“应用”时项数不一致会弹出错误提示，并忽略本次应用；
* 任意一个 match 不存在，或对应捕获组不存在，整条规则失败，继续尝试下一条规则；
* 捕获组存在但没有参与匹配时，该段输出空字符串。

### 3. 识别结果弹窗置顶

针对商店版 QuickLook 预览窗口会遮挡识别结果的问题：

* ResultWindow、GoPanel 和截图成功覆盖层会主动置顶；
* 检测 QuickLook 进程窗口，以 QuickLook 上方窗口作为 Z 序锚点，避免被商店版 QuickLook 覆盖；
* 区域截图识别成功后会保持 Topmost，不再在成功分支中取消置顶；
* 弹窗显示后每 700ms 低频重申，不改变原有自动关闭策略；
* GoPanel 的关闭按钮始终可见，用户可手动关闭；鼠标移出自动关闭仍然保留。

### 4. 扫描提示音

* 设置 → 功能设置新增“提示音”设置；
* “扫描成功”开关控制 du 声；
* “扫描成功且后处理匹配成功”开关控制 di 声；
* 后处理匹配成功时优先 di；di 关闭时回退 du；两者都关闭则静音；
* 四种识别模式共用同一套设置，开启开关时立即试听对应声音。

## 设置保存位置

后处理设置保存在：

    %APPDATA%\MyQrCodeScanner\Settings.ini

## 构建

环境要求：

* Windows
* .NET Framework 4.7.2 或更高版本
* 可构建 net472-windows 的 .NET SDK
* WPF

    dotnet restore MyQrCodeScanner.sln
    dotnet build MyQrCodeScanner.sln -c Release

生成目录：

    MyQrCodeScanner/bin/Release/net472-windows/

## 已知限制

* 当前版本基于上游 v1.52 的代码，尚未包含剪贴板写入异常的重试保护。扫描成功后如果剪贴板正被其他程序占用，可能抛出 COMException 并退出。
* /g 固定展示，不提供 i、m 等额外 flags。
* 正则使用 .NET System.Text.RegularExpressions.Regex，常用 JavaScript 写法兼容，但不是浏览器/Node 的 JS 引擎。
* 所有规则均未匹配时保留原文，避免误清空扫描结果。
